## Сделано

### 1. QA-судья (смысловой контроль)

- **`scripts/qa/eval.ts`** — CLI. Слепое парное сравнение: «старый» перевод (базлайн) vs
  «новый» (рабочее дерево), судья не знает, какая сторона какая. Каждая пара судится ДВАЖДЫ
  в зеркальных порядках A/B; вердикт учитывается только при устойчивых 2:0 (защита от
  позиционного смещения судьи-той-же-модели).
  - Базлайн: `--old-dir PATH` **или** `--git-ref REF` (ровно один). Раскладки old-dir:
    `<dir>/<lang>/<rel>`, `<dir>/<reldir>/<lang>.json` (story/start.json → story/de.json),
    `<dir>/<lang>.json` (плоский снапшот).
  - Остальные флаги: `--langs`, `--sample N` (на файл, по умолчанию 10), `--seed 42`
    (детерминированный сэмпл), `--min-chars`, `--retries`, `--label`, `--out`, `--dry-run`
    (план без модели). Судья ходит только через vLLM.
  - Отчёт: `scripts/qa/reports/<runid>-<label>/report.{json,md}` — сводная таблица по локалям,
    разбивка замечаний по типам/severity, полные тексты пар для спот-чека.
  - Правило «не хуже»: стабильный win-rate NEW ≥ 50% и критических замечаний у NEW не больше,
    чем у OLD.
- **Единица сравнения — блок, не лист**: индексы массивов между локалями могут расходиться.
  `buildComparisonUnits` (`scripts/lib/qa.ts`): строка-лист → блок, массив строк → цельный
  абзац; `unitText(root, path)` достаёт строки из target-дерева в порядке документа.
- **`scripts/prompts/base/qa/judge.txt`** — промпт судьи. Критерии: №1 приятность чтения
  носителю, №2 близость к оригиналу (вольная точность лучше кальки). Плейсхолдеры:
  `{{LANG_STYLE}}` (языковые правила из `scripts/prompts/<lang>/style.txt`), `{{GLOSSARY}}`
  (вставляет eval.ts в формате конвейера). Ответ строгий JSON: `winner|confidence|scores
  0–100|reason|issues` (типы MQM: mistranslation/omission/addition/terminology/style/other;
  severity: critical/major/minor). Часть D (MQM-диагностика «что именно хуже») — из issues.
- **`scripts/lib/qa.ts`** — чистая логика (без модели): mulberry32/hashSeed/shuffleSeeded,
  `parseJudgeVerdict` (async!), `verdictToSides`, `passOrderFor`, `aggregateLang`
  (замечания считаются только из первого прохода), `stableWinRate`, `sumStats`.
- **`scripts/lib/prompt-loader.ts`**: union типа расширен до `'text' | 'ui' | 'keys' | 'qa'`.
- **README** — раздел «Контроль качества: слепой парный судья» с командами.
- Тесты: `tests/qa.test.ts`. На момент передачи `bun test` = **65 pass / 0 fail**.

### 2. Гибкость тегов (решение пользователя: перенос тегов — норма)

- **`scripts/lib/validation.ts`**: сверка тегов переведена с по-листовой на **файловую**
  (пул сигнатур всех листьев, путь проблемы `(файл)`), с диагностикой «в каких листьях»
  избыток/нехватка. Внимание: `diffMultiset(a, b)` = «что есть в a и отсутствует в b» —
  для lost/extra аргументы различаются. Плейсхолдеры остались по-листовыми.
- **`scripts/lib/tag-reconcile.ts`** (новый) + подключён в конец `runPipeline`
  (`scripts/lib/pipeline.ts`, перед контролем полноты): если пул тегов перевода **больше**
  пула оригинала (модель выдумала теги), лишние вхождения срезаются с сохранением текста
  (обёртка `<q>…</q>` раскрывается), не больше глобального избытка — перемещённые теги
  гарантированно не трогаются. Потеря тегов механически не восстанавливается — её ловит
  валидация с ретраями. Лог: `⚠️ [tags] срезаны лишние теги: ...`.
- Промпты: `base/fragments/common.txt` (теги следуют за смыслом; нельзя терять/дублировать/
  выдумывать; кавычки «» НЕ превращаются в `<q>`), `base/text/review.txt` (чек-лист: пул тегов,
  проверка «крючков» в первых элементах), `base/text/tech.txt`, `base/text/fix.txt`
  (фиксеру запрещено трогать теги без явного замечания).
- Тесты: `tests/tag-reconcile.test.ts`, обновлены `tests/validation.test.ts`.

## РЕЗОЛЮЦИЯ (закрыто 2026-09-10)

### Корневая причина — названа точно

Постадийный проб (`/tmp/forensics.ts`, артефакты `/tmp/forensics-out/`) поймал
нарушителей с поличным:

1. **EDITOR** систематически игнорирует контракт «только изменённые ключи» и
   возвращает ПОЛНЫЙ документ (41/41 лист). В пробе его спасла случайность:
   MAIN вернул обёртку `{sourceLocale, targetLocale, data}`, пути патча
   `/data/screen_1/...` не совпали с развёрнутым draft → «применено 0». В
   неудачных прогонах (MAIN без обёртки) этот патч применялся ЦЕЛИКОМ — и
   «полировка» редактора (перестановка цитат в начало экранов, эпиграфы)
   попадала в файл вёрбатим. Это и есть вставка текст-крючка.
2. **FIX** — та же болезнь: при ОДНОМ замечании о типографике вернул полный
   массив `screen_3.texts` (13/13). В пробе контент совпал, но класс
   нарушения тот же.
3. Попутный баг: editor получал сырой `draftText` (с обёрткой-эхом), а патч
   мерджился в развёрнутый `draft` — рассинхрон путей молча превращал стадию
   в no-op.

### Починка (три слоя защиты)

- **`pipeline.ts`**: `mergeSubset` теперь экспортирован и с guard'ом —
  контейнер (массив/объект/корень, ≥4 листьев), покрытый патчем на 100%,
  отбрасывается целиком (лог `⚠️ патч переписывает контейнеры целиком…`),
  остальной патч применяется. Editor'у отправляется канонический
  `JSON.stringify(draft)` вместо сырого `draftText`.
- **`validation.ts`**: новый детект дублей — два РАЗНЫХ ru-оригинала
  схлопнулись в переводе в одинаковый текст (нормализация: теги срезаны,
  только буквы/цифры, ≥20 симв.) → ошибка валидации → автоповтор языка.
  Легитимные повторы (оригинал сам повторяет фразу) не флагуются —
  сравниваются пары путей, а не тексты разных языков.
- **Промпты** `editor.txt`/`fix.txt`: явный запрет возвращать полный
  документ/целые массивы, неизменность порядка и нумерации элементов.

### НОВЫЙ системный факт (НЕ закрыто, отдельная кампания)

Скан пулов тегов по всему дереву (скрипт: логика `/tmp/scan-tag-pools.ts` —
multiset сигнатур тегов ru-файла vs каждой локали) нашёл **468 расхождений**
file×locale: в ru-контенте теги (`<instagram>` ~400, `<q>` ~305,
`<important>` ~261, `<li>` ~199, `<dialog>` ~118, `<activitylink>` ~67,
`<stepper>`, `<step>`, `<discount>`, `<storysettings>`, `<p>`) отсутствуют
в переводах. Причина: ru-контент оброс тегами ПОСЛЕ того, как переводы были
сделаны; state якорит sha1 ru-ключей на первый прогон, поэтому инкрементальность
эти изменения не подхватывает. Лечение — точечный переревод затронутых
file×locale (`--full`), объём большой; решать отдельно.
