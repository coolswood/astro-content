# Локализация: инструкция для AI-агента

Актуальное описание системы локализации. Скрипты-предшественники
(`translate-arb.ts`, `translate-file*.ts`, `translate-ui.ts`, `lingo_proxy.py`,
lingo.dev) удалены — их заменил единый раннер.

## Как устроено

- **Контент**: `src/i18n/ru` → `src/i18n/<lang>` — 19 локалей, раздаётся по HTTP.
- **UI Flutter**: канон `cognitive_psy/lib/l10n/app_ru.arb` → `app_<lang>.arb`
  (merge-валидатор cognitive_psy жёстко требует отсутствия лишних ключей —
  purge мёртвых ключей обязателен).
- **Раннер**: `scripts/translate.ts` (bun). Два режима: контент и `--ui`.
- **Конвейер единый для контента и UI**: main → editor → review → fix
  («критикуй отдельно, правь отдельно»), 4 стадии; язык выбирает семейство
  промптов (`base/text/*` — нарративы, `base/ui/*` — интерфейс). MAIN по
  умолчанию отвечает path-map (плоская карта «путь → перевод»), фолбэк чанка —
  документный формат. UI-режим: payload — плоская карта «ключ ARB → ru» без
  @-меты; мета (описания ролей, placeholders) уходит отдельным полем `meta`
  запроса, фильтруясь по ключам чанка, и в перевод/пути не попадает. Ключи
  чанкуются как контент (≤40 листьев, `--chunk-leaves`), чанки собираются в
  скелет, история принятых переводов последних 50 пар + окно `uiContextWindow`
  (соседние по канону ключи) идут в `context`. После перевода — **коллегия**
  (`scripts/lib/judge.ts`, для ui — промпты `audit_ui_*`: плейсхолдеры {…}/ICU —
  critical, роль строки по @-мете, лаконичность), подтверждённые рекомендации
  вписываются механически и локаль пересматривается — до раунда без правок
  (не более 3; `--no-judge` отключает). Стадия issues коллегии чанкуется по
  ≤40 листьев. Адрес правки — путь листа: цитата current/fragment сверяется
  нормализованно (кавычки/тире/пробелы) с порогом сходства (скип < 50%) —
  точное цитирование моделью не предполагается. Валидация правок
  пер-листовая: ломкая правка (потеря тегов) скипается одна, а не отменяет
  весь батч.
- **Пер-листовой guard правок стадий** (editor/fix/tech, `stageEditRejections`
  в `pipeline.ts`): каждая изменённая пара «черновик → патч» проверяется
  механически — пул тегов и плейсхолдеров не уменьшился, текст не схлопнулся
  (<35% длины), сходство ≥30% (не тотальная подмена), нет новых соседних
  задвоений («als als», 覆い覆い). Ломкая правка отбрасывается по одной
  (лист остаётся на значении черновика) с warning. Размер чанка перекрывается
  флагом `--chunk-leaves N`: тест ≤20 — паритет на старом конвейере, а на новом
  (path-map + guard'ы + контекст editor'а) проигрыш 29% — дефолт ≤40 подтверждён
  дважды, мельчение не улучшает. Полный прогон de 2026-09-12: `--chunk-leaves 15`
  на tests/* дал потерю сабтриев (/steps целиком) —editor на длинных массивах
  отвечает массивом-эхом с null'ами; для расщепления «смысловых якорей»
  (соседние близкие пункты) мельчение не помогло.
  Thinking-режим модели (`StageRequest.thinking`) на editor-стадии проиграл
  слепое сравнение (33%) — не используется.
- **Path-map — формат ответа MAIN по умолчанию** (отказаться: `--no-main-path-map`):
  main возвращает плоскую карту «путь → перевод» по явному списку путей — сдвиг
  содержимого между соседними листьями («крючки») структурно невозможен, полнота
  проверяется по путям на месте, recovery почти не нужен. Батч de (3 статьи +
  perfectionism): слепой win-rate 88% (14:2 стабильных пар), стадии быстрее
  (jsonMode с первой попытки), потерь листьев ноль. Известное ограничение:
  монотонно-повторяющиеся секции (таблицы-колонки, однотипные пункты) могут
  зациклить генерацию карты (story/distortions/love.json: клин перемежающийся,
  сырой ответ обрезается по капу токенов) — упавший чанк автоматически
  перегоняется документным форматом (пер-чанковый фолбэк в `runPipeline`),
  файл не теряется; love после фикса — eval 83%. Полный прогон de 2026-09-12
  дополнил два механизма: (1) потеря >30% путей чанка — исключение → тот же
  документный фолбэк (клин часто приходит как МОЛЧИВАЯ неполная карта: trap
  1/33 путей, sociophobia 1/40 — раньше это ловил только recovery, а >30%
  валивало попытку целиком); (2) документ-массив в корне (articles, questions,
  homeBot/*, texts/psychologist) заворачивается в `{content: …}` на входе
  конвейера — без обёртки mergeSubset отбрасывал массив-черновик целиком,
  файл терял все листья на любой попытке.
- **Валидатор дублей против «крючков»** (validation.ts, п.7): два разных
  ru-оригинала не могут получать одинаковый перевод. ё/е сворачиваются
  («Обостренное/Обострённое» в bdi — один текст). Близкие пары, которые модель
  стабильно унифицирует (шкальные легенды «Крайне выраженные…/Выраженные…»,
  соседние пункты, парафразы-близнецы daybook), чинит **точечная разведка пар**
  (`scripts/lib/duplicate-repair.ts`): при отказе валидации по дублям (≤8
  групп, kind=text) вместо потери попытки — маленький запрос с обоими
  оригиналами рядом и явным требованием различия (формат ответа — path-map
  {paths}), правки через пер-листовой guard, затем повторная валидация.
  Полный ретрай файла остаётся для прочих причин отказа. Немецкие
  «sie Sie»/«die die» — грамматика, а не задвоение: финальный скан дублирования
  даёт warning, не блокировку.
- **Внешний аудит и эксперимент prompt-v2** (2026-09-13): слепой судья-гемма
  заякоривается на устоявшихся терминах глоссария и может ошибочно браковать
  ПРАВИЛЬНОЕ разведение терминов (п perfectionism: «альтернативное убеждение»
  → alternative Überzeugung судья предпочёл как «нарушение глоссария», хотя
  внешний аудитор gpt-6-astra требовал именно разведения). При арбитраже
  терминологических споров авторитетнее внешний аудитор. Эксперимент с правками
  по аудиту (style.txt 8–10, review «точность действий», глоссарий 25 терминов):
  терминологические файлы улучшились (common 3:0, quotes 2:0), нарративные —
  паритет в пределах шума перевода (стабильные NEW 4 : OLD 12 при 11
  нестабильных парах — полный переперевод сам по себе перекидывает «монетку»
  на каждом блоке), поэтому нарративы оставлены на предыдущей версии, правки
  промптов приняты для будущих прогонов.
- **Контекст принятых переводов** (ui): в запросе перевода и в коллегии
  поле `context` — до 50 ближайших по каноническому порядку уже принятых
  переводов (`uiContextWindow`). Задача — единый стиль и уникальность
  однотипных списков (эмоции/категории: разные ru-ключи не могут получать
  один перевод); правило продублировано в `base/ui/main.txt` и
  `audit_ui_issues.txt`. Осцилляции (возврат листа к бывшему значению)
  и потеря тегов блокируются. Отчёты — `scripts/qa/reports/<ts>-judge-*/`. Промпты
  в `scripts/prompts/` (эти файлы — выверенный актив качества, НЕ менять без
  явной задачи). Патчи editor/fix применяются с пер-листовым guard'ом
  (`stageEditRejections` в `pipeline.ts`): потеря тега/плейсхолдера, схлопывание
  текста, тотальная подмена и новые задвоения отбрасывают ЛИСТ, а не весь
  патч (исторический контейнерный guard «100% покрытый контейнер отбрасывается»
  заменён пер-листовым).
- **Точечная добивка невалидных листьев** (`translateWithRetries`): провал
  валидации попытки не перегоняет весь файл — проблемные листья
  (`collectProblemPaths`: пустые/потерянные, по-листовые замечания
  (плейсхолдеры, чужие алфавиты), группы дублей, локальный разбаланс тегов)
  проходят полный конвейер на мини-payload, ответ вписывается по путям
  (`mergeSubset`), валидация повторяется до 2 проходов. Кап добивки —
  max(6, 25% листьев); больше — системный сбой, полный ретрай. Канарейка
  de 2026-09-13: лишний `{count}` в одном листе из 200 чинился 4 запросами
  вместо 6-минутного перегона файла. Дубли (text) чинятся разведкой пар
  (`scripts/lib/duplicate-repair.ts`) — она работает ДО добивки.
- **Анонимный прогон застрявших листьев**: модель якорится на осмысленном
  английском ключе («breathing_sec_left» → выдуманный {count} вопреки мете,
  негативному примеру и правилам промпта — проверено зондами). Листьям, не
  спасённым добивкой, ключ в ЗАПРОСЕ нейтрализуется (item_1, item_2, …),
  перевод идёт по ru-тексту и мете, ответ маппится обратно. Шаг лестницы
  эскалации: конвейер → добивка (2 прохода) → анонимный прогон → полный
  ретрай → спасение листа. Зонд: item_1 + та же мета = 3/3 чистых
  «Sek. übrig» против 0/6 с настоящим ключом.
- **Спасение листа**: если после всех попыток лист невалиден, но в целевом
  файле есть валидный старый перевод — старый остаётся, файл записывается
  (громкий warning со списком ключей). Некрытый лист (нет ни валидного
  нового, ни старого) — провал как раньше.
- **Recovery потерянных листьев** — до 2 проходов по остатку; принимает
  ответ-карту путей (модель в ui-режиме привыкла к path-map), но только если
  ВСЕ пути карты указывают на потерянные листья; path-map в main толерантен
  к потере ведущего `/` в пути (bare-ключ засчитывается). Известное слабое
  место: добитые recovery листья лишены контекста чанка и могут выбрать
  бытовое слово вместо КПТ-термина (канарейка de: «Принятие» → Annahme
  вместо Akzeptanz; термин внесён в глоссарий de, ключ перегнан точечно).
- **Канарейка**: `--limit-keys N` (ui) прореживает todo равномерно по
  каноническому порядку — прогон покрывает весь файл, а не одну алфавитную
  зону. Слепое сравнение с базлайном: `bun scripts/qa/eval.ts --ui
  --old-dir backups/<снапшот> --langs de --sample 30` (NEW = рабочее дерево
  app_<lang>.arb, OLD = <old-dir>/<lang>.json; @-мета исключена).
  Первый прогон de (200 ключей, 5 партий, коллегия 3 раунда/15 правок):
  win-rate NEW 65% (15🟢/8🔴/7🟡, критических 1:1) — правило «не хуже»
  выполнено; отчёт `scripts/qa/reports/20260913-112606-ui-canary-new-pipeline/`.
- **UI-специфика (мобильное приложение)**: промпты `base/ui/*` держат
  ДЛИНУ строки ≈ оригинал (±30%: вёрстка рассчитана на длину русской строки;
  для title/кнопок компактность важнее полноты), завершённость по образцу
  оригинала (точка/двоеточие/многоточие),
  плейсхолдеры {name} символ-в-символ, ICU {count, plural, ...} с категориями
  целевого языка, разметку <b>/<p>/<discount> и переносы строк, уникальность
  однотипных списков. Роль строки (кнопка/заголовок/тост/пояснение) модель
  берёт из английского ключа и поля `meta` (@-мета ARB). Механика — та же, что
  у контента: path-map, чанки ≤40, editor→review→fix, пер-листовой guard,
  recovery. Поверх — `warnUiBloat` (translate.ts): не-блокирующие warning на
  разбухание (>3× длины оригинала) и пробелы по краям — окончательное решение
  за коллегией. Дубли текста для ui не чинятся разведкой пар (короткие лейблы
  легитимно повторяются) — уникальность списков держат context и коллегия.
  Регрессия 2026-09-13: `chunkPayload` считал скалярные листья нулём — плоская
  карта строк (ui-payload) резалась в ноль чанков и валилась «потеряны ключи
  N/N»; фикс `max(countLeaves(v), 1)` покрыт тестом.
- **Роли спорных ключей** — `scripts/prompts/base/ui/notes.json` (ручной
  актив): для ключей без описания в @-мете в поле `meta` запроса подставляется
  note о том, ГДЕ строка живёт (таб профиля vs фото, кнопка vs поле, короткий
  title диалога). Источник истины — использование ключа в коде
  cognitive_psy (`rg "\.getterName" lib -g '!app_localizations*'`): канарейка
  de показала, что без роли модель калит смысл («portrait» → Porträt вместо
  Persönlichkeitsprofil), а следование длине ru ломает UI там, где роль
  требует короткого заголовка (force_update_title).
- **Петля внешнего ревью**: правки носителя языка применяются механически
  (таблица «ключ → текст» + `validateTranslation` перед записью), выводы —
  в промпты и notes. Первый ревью канарейки de (2026-09-13): 8/10 vs 6/10
  у старого; главных претензий три — длина (см. выше), роли (notes.json),
  единообразие Sie/Ihre (de/style.txt: безличное «man» — только в словарных
  определениях искажений; чек-лист коллегии `audit_ui_issues` это проверяет).
- **Конвенция `<instagram>`**: встраиваемый пост рендерится только для ru и en
  (там допустимы атрибуты `ids="…"`); во всех остальных локалях тег обязан быть
  ПУСТЫМ. Промптовое правило модель нарушает, копируя тег дословно, поэтому
  `runPipeline` срезает атрибуты механически
  (`stripInstagramAttributes` в `scripts/lib/tag-reconcile.ts`).
- **Провайдер по умолчанию**: vLLM `google/gemma-4-26B-A4B-it` через SSH-туннель.
  Старые браузерные провайдеры (ChatGPT/Claude/Gemini/Mistral по CDP :9222)
  сохранены в `scripts/lib/providers/` с пометкой LEGACY, доступны через
  `--provider chatgpt|claude|gemini|mistral`, не развиваются.

## ⚠️ Лимит модели

**К модели — не более `concurrency` (по умолчанию 6) одновременных запросов.**
Раннер держит общий семафор в `VllmClient` (по умолчанию жёсткий 1 — судья и
QA-инструменты ходят по одному) и гонит задачи файл×язык пулом воркеров.
Запросы уходят с **пониженным приоритетом** (`requestPriority`, по умолчанию 10):
vLLM запущен с `--scheduling-policy priority`, где *меньше = раньше*, поэтому
интерактивные потребители модели обгоняют перевод, а каналом перевод не владеет.
Замер скейлинга 2026-09-13 (12 запросов × 220 ток): 3 → 138 ток/с, 6 → 237
ток/с (+72%), 8 → плато; латентность интерактивных запросов при этом 4.8с →
5.4с — дефолт 6, для фоновой ночной работы можно `--concurrency 8`.

## Команды

```bash
# Посмотреть, что переводится (missing/changed/dead по всем локалям), ничего не меняя
bun scripts/translate.ts story/start.json --dry-run
bun scripts/translate.ts --ui --dry-run

# Перевести контент-файл (или каталог) на все языки / на один
bun scripts/translate.ts story/start.json
bun scripts/translate.ts story/automatic.json --langs ja,ko
bun scripts/translate.ts story --concurrency 3        # 3 параллельных запроса (по умолчанию)
bun scripts/translate.ts story --concurrency 1        # осторожно, как раньше — по одному
bun scripts/translate.ts story --priority 0           # приоритет как у всех (по умолчанию 10, фон)

# Доперевести/обновить интерфейс cognitive_psy
bun scripts/translate.ts --ui
bun scripts/translate.ts --ui --langs en,de

# Полный переперевод, игнорируя инкрементальность
bun scripts/translate.ts story/start.json --full
```

Раннер сам: детектит недостающие/изменившиеся/мёртвые ключи, валидирует
(ключи, плейсхолдеры `{…}`, теги `<b>/<q>/<important>/<instagram>`, алфавиты,
дубли — два разных ru-оригинала не должны схлопываться в одинаковый перевод;
ловит «крючки»-подмены первых элементов), ретраит с
`response_format: json_object`, пишет файлы атомарно и только после
успеха (частичной записи нет), ведёт закоммиченный state
(`scripts/translation-state.json`, per-key sha1 ru-значений; первый прогон
инициализирует его существующими переводами — изменение ru-ключа после этого
всегда ловится).

## Глоссарии

`scripts/prompts/<lang>/glossary.json` — ручной актив (НЕ генерировать моделью):
термины КПТ извлечены из проверенных переводов проекта. Для de, ja, pl, pt_br —
исторические; для ar cs en es fr he id it ko nl pt sv tr — составлены в сессии
редактуры 2026-09-10 по образцу ja. Без глоссария модель калькирует термины
(«глубинные убеждения» вместо принятых core belief / creencias nucleares /
핵심 신념 и т.д.).

## Валидация отдельно

```bash
bun check-translations.ts <lang>   # чужие алфавиты по всему каталогу локали
bun scripts/canonicalize-media-paths.ts   # медиа-пути (img/video): сегмент — en (ru — ru); --apply исправляет
bun test                           # тесты state/диффа/валидации/дерева
```

Медиа-пути (`stories.json`: поля img/video) не переводятся: картинки
локализованы только для en и ru (все языки кроме ru ссылаются на `en`);
видео существуют только для ru — видео-поля в не-ru локалях не переводятся
и выпиливаются как «мёртвые» (см. `scripts/lib/media-paths.ts`).
Конвейер восстанавливает такие пути автоматически; валидация (правило 3.7)
отклоняет лист с изменённым путём — включая правки коллегии.

## Аудит статьи: судейский пайплайн

```bash
bun scripts/qa/audit.ts breathing.json --key balance --langs de,ar --label ручной-замер
```

Три стадии (каждая — отдельный запрос, промпты `base/qa/audit_*.txt`):
**issues** (построчный scan + замечания: тип/severity/цитата/почему) →
**deliberate** (коллегия: перекрёстная сверка замечаний между собой и с
оригиналом — confirmed/merged/rejected + ранжирование) → **recommend**
(сравнение вариантов решений, выбор лучшего, общий вердикт
score/verdict/summary). Флаг **`--apply`** добавляет шаг корректировки:
подтверждённые рекомендации механически вписываются в файлы локалей
(без модельного прохода; с проверками пути, `current` и валидацией
тегов/плейсхолдеров — при провале файл не пишется). Отчёт —
`scripts/qa/reports/<ts>-audit-<label>/`. Отличие от слепого парного
судьи (`qa/eval.ts`): тот сравнивает ДВА перевода между собой, аудит
разбирает ОДИН перевод и выдаёт готовые рекомендации «что и как заменить».

## Merge-back победителей слепого сравнения

```bash
# UI (arb + снапшот легаси):
bun scripts/qa/merge-winners.ts --report scripts/qa/reports/<dir> \
  --old-dir backups/<снапшот> --arb ../cognitive_psy/lib/l10n/app_en.arb --apply
# Контент (базлайн OLD из git — состояние до переперевода):
bun scripts/qa/merge-winners.ts --report scripts/qa/reports/<dir> --git-ref <ref> --apply
```

Замыкает цикл качества: eval.ts измеряет, merge-winners забирает тексты-победители
OLD для стабильных поражений NEW (2:0). Ограждения: существование ключа/пути,
validateTranslation конвейера, легаси-терминология (skip «нужен перегон»),
плейсхолдеры ru-канона, (контент) OLD сверён с pair.oldText; после виртуального
мерджа — файловая валидация. Dry-run по умолчанию: план → merge-winners.dry.md,
apply → merge-winners.md. Итеративная схема: eval со свежим seed → merge-back →
повтор, пока инструмент применяет переносы; контрольный замер на новом seed даёт
плато. Пилот en UI: win-rate 59% → 86% (тот же seed), свежие сэмплы 47–59% → 71%
(3 волны, 28 ключей). ⚠️ Контент: не применять к файлам с ручной редактурой без
сверки — отличие OLD может быть намеренным решением (напр. en story/start.json).
